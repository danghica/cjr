# Deterministic Rocq-to-HTML specification renderer

## Summary

Build a local Python CLI that renders Rocq declarations as programmer-readable pseudocode in static HTML, without proofs or generative methods.

**The project boundary is the current working directory and its subdirectories.** Discover Rocq source files recursively within that boundary. All generated symbol links stay within the generated project documentation; external dependencies and libraries receive no links.

Use coq-lsp 0.2.5+8.20 with the repository’s Coq 8.20.1. [Backend compatibility](https://opam.ocaml.org/packages/coq-lsp/coq-lsp.0.2.5%2B8.20/).

## Discovery, parsing, and linking

- Provide `rocq-readable build --output generated/spec-html`, with optional `--dictionary FILE`, `--learn`, and `--strict`.
- Retain `rocq-readable render FILE --name DECLARATION --output FILE.html` for individual declarations.
- Discover all `.v` files recursively, including files absent from `_CoqProject`. Exclude Git metadata and the output directory; do not follow directory symlinks outside the project root.
- Use `_CoqProject` and `_RocqProject` for parsing configuration and load paths, rather than as source inventories. Apply the nearest ancestor configuration within the project boundary.
- Use Rocq’s AST and document state for declaration boundaries, imports, scopes, notation, and local context. Earlier proofs may be checked to establish context; proof bodies never appear in output.
- Render definition bodies, proposition statements, and named type declarations, including constructors and record fields.
- Generate an index and one HTML page per source file, preserving relative directory structure and declaration order.
- Build a symbol index before rendering. Assign stable anchors from qualified Rocq identities and link resolved occurrences to their generated declarations, including forward and recursive references.
- Preserve symbol links through dictionary renaming. Link local variables to their binders without confusing them with global symbols.
- External symbols remain readable, unlinked text. Do not generate pages for external libraries, dependency URLs, or external source links.
- Unsupported declarations retain anchors and marked source representations. Report parsing failures per file and continue generating other pages; any failed file makes the build exit unsuccessfully.

## Pseudocode and HTML

- Render applications as calls; definitions as functions or predicates; and matches, conditionals, lambdas, quantifiers, and recursion as structured pseudocode.
- Multiline scope uses four-space indentation and a colon, with **no enclosing scope brackets**. Dedentation closes the scope.
- Use scope brackets only when the entire scoped expression occupies one line. Multiline calls use indented arguments without enclosing parentheses.
- Retain brackets serving a data purpose, such as list literals, indexing, and tuples.
- Preserve whitespace without automatic line wrapping; use horizontal scrolling on narrow screens.
- Preserve binder order, explicit types, implicit markers, typeclass assumptions, and surrounding context.
- Distinguish implication, resource-consuming implication, entailment, conjunction, separating conjunction, pure assertions, persistence, and later modalities.
- Seed CJR/Iris rendering rules for ownership, block ownership, object fields, weakest preconditions, and big separating conjunctions. Preserve explicit WP options and postcondition binders; explain partial correctness.
- Preserve unknown calls and mark unsupported syntax using original source. Do not automatically unfold predicates, simplify statements, or remove premises.
- Produce escaped static HTML with local CSS, relative links, declaration navigation, and expandable proof-free source excerpts. Viewing requires no network connection.

## Dictionary and interaction

- Store a versioned JSON dictionary containing user-authored names and structured rendering templates.
- Match parsed applications and notation nodes using available identity, scope, and argument-shape information; never perform global textual substitution.
- Templates specify layout and placeholders rather than raw HTML. The renderer controls indentation, brackets, escaping, and links.
- Preserve every matched argument and binder. Templates cannot execute code.
- With `--learn`, show unfamiliar constructs and numbered placeholders, accept a rule, validate it, generate an HTML preview, and save after user acceptance.
- Support skipping, replacing, and removing rules. Ordinary rendering never changes the dictionary.
- Structural preservation is tested; arbitrary user wording remains a human-reviewed presentation choice.

## Validation and defaults

- Test representative CJR definitions and contracts, including swap, list, array, and most-frequent.
- Verify recursive discovery includes unlisted `.v` files and excludes sources outside the directory boundary.
- Check every generated internal link has a destination. Test cross-file references, recursion, renamed symbols, constructors, fields, and shadowed variables.
- Confirm external-library occurrences are unlinked and no generated link leaves the documentation.
- Test indentation-only multiline scopes, bracketed inline scopes, nested layouts, HTML escaping, and narrow-screen presentation.
- Cover notation scopes, logical distinctions, unknown syntax, malformed dictionaries, backend failures, and dictionary save/reload.
- Require deterministic output for identical sources, backend, and dictionary. Add a dedicated test target, usage documentation, and visual inspection of representative pages.
- Initial delivery is CLI-driven static HTML with CJR/Iris vocabulary. Editor integration, browser rule editing, executable transformations, and formally verified rendering equivalence are deferred.

# Verified quadtree example with an HTML report index

## Summary

Create a self-contained integer-point quadtree example under `quadtree/`, reusing the shared CJR/Iris framework and Gallina printer.

The final deliverable is **`quadtree/index.html`**: an offline HTML index linking individual rendered definitions and lemmas, extracted Cangjie files, the test report, and the benchmark report.

## Interface and algorithm

- `make(depth)` creates an empty tree covering `[0, 2^depth) × [0, 2^depth)`, requiring `0 ≤ depth ≤ 30`.
- `insert(tree, x, y)` returns `true` exactly when it adds a new in-bounds point. Duplicate or out-of-bounds insertion returns `false` and preserves the tree.
- `contains(tree, x, y)` returns exact membership; out-of-bounds coordinates return `false`.
- `range(tree, xmin, ymin, xmax, ymax)` returns a duplicate-free linked list of matching points. Rectangles are half-open; empty or reversed rectangles produce empty results. Result order is unspecified.
- Nodes are empty leaves, single-point leaves, or four-child branches. Quadrants are lower-left, lower-right, upper-left, upper-right; midpoint coordinates belong to upper/right halves.
- Splitting redistributes the existing point before inserting the new point. Distinct integer points separate before reaching unit cells.
- Store node bounds and branch midpoints. Calculate subdivision sizes using a verified doubling helper and existing CJR arithmetic.
- Range traversal prunes disjoint nodes and accumulates results without repeated concatenation.

## Specification and verification

Define a finite-set specification and executable Gallina reference model. For fixed domain \(D\), let \(I_p(S)\) insert an in-bounds point and \(Q_R(S)\) select points inside rectangle \(R\).

Prove:

- **Insertion commutativity:** \(I_p(I_q(S)) = I_q(I_p(S))\), including duplicate and rejected coordinates.
- **Insertion idempotence:** \(I_p(I_p(S)) = I_p(S)\).
- **Repeated-query idempotence:** repeated membership calls return the same Boolean; repeated range calls return equivalent duplicate-free lists while preserving the tree’s fields and structure.
- **Range distribution over union:** \(Q_R(S \cup T) = Q_R(S) \cup Q_R(T)\), for trees sharing a domain. Union is specification-level set union, with overlapping points included once.
- Subdivision coverage/disjointness, bounded depth, uniqueness, and exact operation semantics.

Equality in insertion laws concerns represented point sets. Query results are compared as sets or permutations; fresh allocations are allowed.

Define Iris ownership predicates for trees and result lists. Prove operation contracts and derive concrete operation-composition theorems validating the algebraic laws. Query contracts preserve the same structural tree model.

Use `Int64` coordinates and query endpoints, and prove stored-bound and midpoint calculations stay within its limits. Verification must pass `coqchk` and assumption auditing without admissions or new axioms.

## Directory layout and final HTML report

Keep example-specific specification, algorithm, proofs, extraction entry point, generated code, tests, benchmarks, results, and documentation under `quadtree/`. Provide local `build`, `verify`, `extract`, `test`, `benchmark`, `docs`, and `report` targets.

Root changes are limited to load paths, build/verification wiring, a README pointer, and required repository logs.

The report index contains:

- **Definitions and lemmas:** grouped by specification/model, algorithm, ownership predicates, correctness, and algebraic laws. Each entry links directly to its declaration anchor in a page generated by `rocq_readable`, with proofs omitted. Build this index from the renderer’s generated declaration navigation and stable anchors.
- **Extracted Cangjie:** list every generated `.cj` file, linking both the original file and an escaped HTML source view. Extract implementation code directly from verified CJR definitions.
- **Test report:** link an HTML report containing case results, randomized/algebraic validation summaries, compiler information, source hashes, and execution status.
- **Benchmark report:** link an HTML report containing workload descriptions, timing summaries, local charts, comparison methodology, machine/compiler metadata, and downloadable raw CSV/JSON results.
- **Verification summary:** show proof-checking and assumption-audit results, along with renderer errors or unsupported-syntax coverage.

Use relative links, local CSS and chart assets, escaped content, and no network dependencies. All report destinations remain inside `quadtree/`.

`make report` assembles the index after verification, extraction, documentation, tests, and benchmarks. Assembly fails if required artifacts are missing or recorded source hashes are stale. Keep generated HTML, extracted code, and report data in version control.

## Tests, benchmarks, and acceptance

Test empty trees, depth zero, domain boundaries, midpoint routing, duplicates, rejected coordinates, all quadrants, and deeply clustered points. Cover empty, reversed, disjoint, selective, overlapping, and whole-domain rectangles.

Validate algebraic laws on the unchanged extracted code:

- Insert point pairs in both orders and compare complete contents and membership.
- Repeat queries and check equivalent results and unchanged tree contents.
- Build trees representing \(S\), \(T\), and \(S \cup T\), then check range distribution with deduplicated result sets.
- Run seeded randomized operation sequences and insertion-order permutations against an independent flat-set oracle.

Compile and run using Cangjie 1.0.5, with configurable compiler and SDK paths.

Benchmark extracted CJR against an independent native Cangjie quadtree with identical semantics and subdivision policy, plus a flat collection using hash-indexed membership and range scanning. Use uniform, clustered, and deeply coincident-prefix datasets at 256, 4,096, and 16,384 unique points. Measure construction/insertion, membership hits/misses, and empty, selective, broad, and whole-domain queries.

Use two warmups, calibration toward 20 ms batches, seven trials across three processes, rotating implementation order, and allocation-aware repetition limits. Validate complete results outside timing and consume checked checksums inside measured batches. Save raw observations, medians/IQR, source hashes, compiler flags, machine metadata, and charts.

Acceptance requires completed functional and algebraic proofs, reproducible extraction, passing runtime tests, measured benchmarks, and a complete HTML index whose file links and declaration anchors all resolve. Visually inspect the index and representative linked pages at desktop and narrow widths.
