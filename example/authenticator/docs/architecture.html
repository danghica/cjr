The application has one memory-only CJR core and two driving adapters: a Cangjie CLI and a macOS SwiftUI app. The core proof gate passed before frontend implementation. No web adapter is planned.

Dependency rule

cli/ and ui/ depend on the application contract defined by core/. The core imports neither frontend nor operating-system APIs. In particular, Swift types, terminal input, clocks, URI syntax, text encoding, and clipboard operations must not enter Rocq models or CJR implementations.

The core's source lives in core/rocq/, its generated Cangjie in core/extracted/, its native tests in core/test/, and its extraction/test runner in core/scripts/. Shared documentation remains in docs/.

Driving port: account application operations

The existing application port consists of authNew, authDestroy, authAdd, authList, authRead, authRename, authRemove, and authCode, together with authRemaining. Its precise pointer, length, return-status, and lifetime contract is documented in the API reference.

An enrollment request contains normalized label and issuer bytes, Base32 secret characters, digit count, and period. The core owns validation of these values, secret decoding, account capacity, monotonic identity, state mutation, and OTP calculation. The adapter owns parsing and presentation. A code request contains an explicit timestamp; it does not ask the core to read a clock.

The standalone hash, HMAC, HOTP, TOTP, and Base32 functions are core library operations, not user commands. Copy/zero/byte-check/round/find helpers are implementation details and must not become frontend commands or FFI exports.

External capabilities and their adapters

  • Time input: each frontend supplies nonnegative Unix seconds to the driving port. CLI uses a system-clock adapter or explicit deterministic test input; SwiftUI uses its system-clock adapter when refreshing. Tests use fixed time. No clock dependency or clock implementation belongs in the core.
  • Enrollment input: the CLI and UI normalize manual input or an otpauth://totp URI into the application request. URI parsing rejects unsupported algorithms/types and ambiguous fields before invoking the core. Parsing must not implement Base32 decoding, hashing, or OTP calculation.
  • Presentation: CLI formats output through its terminal adapter; SwiftUI formats metadata, zero-padded codes, countdowns, and clipboard actions through its view/application adapter. Neither adapter stores secrets in output or diagnostics.
  • Memory: CJR allocation, load/store, and free primitives are the core's modeled memory boundary. Their extracted calloc/free implementation is a trusted runtime adapter, with allocation success an explicit assumption. Heap ownership and buffer bounds are proof obligations, not frontend decisions.

Composition and lifetime

Each executable owns one session and wires its input/time/presentation adapters to the application port. Sessions are independent. Every access to a session is serialized, and the owner destroys it exactly once after all calls finish. The CLI composition root belongs in cli/; the SwiftUI composition root and Cangjie-to-C ABI bridge belong in ui/.

The FFI adapter translates opaque handles, fixed-width scalars, length-delimited buffers, and status codes only. Swift objects, Cangjie runtime objects, and exceptions do not cross the ABI. Cangjie runtime initialization and execution-thread requirements belong in that adapter and its integration tests, not in the core. The bridge calls the same extracted application operations as the CLI; it does not reimplement them.

Completed proof gate

All crypto, encoding and account heap contracts now compile, including enrollment and abstract session-state correspondence. The exported contracts instantiate proved callees. Finite input-heap views cover overlapping read-only buffers. The 69-module core audit passes: coqchk exit 0 and all 580 declarations with closed assumptions. All nine native test groups pass. The precise evidence and trusted boundary are recorded in core proof status.

Concrete adapters and composition

cli/ports.cj defines the command layer's AccountPort and ClockPort. CoreAccounts adapts the extracted application operations to typed enrollment and metadata values; Words owns and clears its temporary buffers. The command loop depends on these ports. cli/enrollment.cj is the text/URI adapter and SystemClock is the wall-clock adapter. cli/main.cj is the CLI composition root.

ui/AccountPort.swift defines the Swift driving and time ports and enrollment adapter. CoreSession.swift implements the driving port through the C ABI. ui/bridge.cj dispatches account operations to the unchanged extracted Cangjie. runtime.c is the Cangjie runtime/scheduler adapter: it initializes the runtime once, initializes the core library, submits each invocation with RunCJTask, waits synchronously, and releases the runtime task handle. A mutex serializes calls. The runtime stays alive until process exit. Its header comes from the pinned Cangjie runtime source (runtime/src/Cangjie.h).

AuthenticatorBridge.h is the sole Swift ABI contract. Its opaque owner contains the core pointer; the core layout is never visible to Swift. Buffers are borrowed for one synchronous call with explicit word capacities. The shim validates field bounds and output capacity before dispatch, copies request buffers, then clears the copy. Status -10 identifies bridge/runtime/shape failures. Destruction frees the owner exactly once; stale and foreign C handles are invalid. CoreSession serializes its calls with close and makes repeated Swift close calls harmless. Allocation success inside the extracted core remains an explicit proof assumption.

SessionModel is the main-actor application adapter. It composes AccountPort and ClockPort, holds secret-free presentation values, and drives fresh code requests on timer ticks. SwiftUI views use this adapter. The clipboard action is an AppKit presentation adapter. AuthenticatorApp is the SwiftUI composition root and destroys its session on termination. No secrets are persisted.

scripts/frontends.py is build orchestration outside the core. It verifies source fingerprints against passed core evidence, then builds with the exact extraction, removing only its known empty-main boilerplate in a build copy. For the dylib it also prepends a package header. No algorithm body is patched. Shared URI fixtures live in test/; frontend integration tests exercise the real extraction, not replacement crypto implementations.
