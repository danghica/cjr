The core proof gate passed on 27 October 2026. All 69 modules passed coqchk and all 580 declarations have closed assumptions. CLI and SwiftUI implementation may now proceed; extracted runtime tests also pass.

Completed concrete proof families

  • Buffer allocation/free, slice ownership and reassembly, copy and zero-fill, byte validation, counted loops, and finite input-heap views. Input views allow overlapping read-only sources to be borrowed and restored sequentially.
  • SHA-1 native padding construction, schedule loading/expansion, all 80 rounds, feed-forward, aligned block iteration, digest encoding, entry validation and cleanup. sha1_entry.sha_refinement_proved proves the full exported success contract with source capacities and preserved output suffix; sha1_reject covers invalid bytes and sizes without writes.
  • HMAC normalization and both hashes, HOTP counter encoding and dynamic truncation, decimal reduction, and TOTP. core_crypto instantiates the SHA-1 proof, so its public success contracts have no assumed callee refinement. HMAC supports overlapping key/message inputs. Rejection contracts cover all size, byte, digit, period, counter and timestamp guards. Separate bounds files establish the extracted arithmetic's Int64 domains and intermediate bounds.
  • Canonical Base32 streaming equivalence, scanning, final validation, allocation, commit and cleanup. base32_contracts covers every size and failure path; rejected inputs leave the destination unchanged. base32_input connects it to finite input heaps for enrollment.
  • Session initialization/destruction, exact lookup/listing, metadata read, complete removal and rename, metadata/secret clearing, rejection atomicity, and read-only account-code dispatch. Rename accepts overlapping label/issuer inputs. Concrete listing order is slot order; the abstract account collection is related up to permutation.
  • Complete enrollment validation, Base32 decoding, capacity/identifier guards, slot commit and temporary scrub/free, with all three read-only inputs allowed to overlap. Every failure preserves the session.
  • Abstract account correspondence and validity preservation for removal, rename and enrollment. core_accounts composes all eight application operations over session_at, including exact metadata and code results. No callee refinement remains assumed in those exported contracts.
