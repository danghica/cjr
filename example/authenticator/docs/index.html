Authenticator core API

Account sessions, SHA-1 one-time passwords, and Base32 decoding. Every entry documents its arguments, result, memory effects, and current proof links.

This reference covers all 20 functions emitted by the CJR extraction. Account operations and authRemaining form the driving application port used by the Cangjie CLI and SwiftUI FFI adapter. Standalone cryptography and encoding functions are core library operations; internal helpers are listed for completeness. See the application guide for frontend usage.

Core implementation contracts are checked. Each implementation contract is checked against the extracted CJR body and its calling preconditions. The complete core audit covers all exported functions; related model and component links provide supporting results. Compiler/runtime and extraction remain trusted boundaries. WP lemmas express partial correctness, without a termination guarantee. Links open the documentation generated by rocq-readable under docs/rocq. Those pages omit proofs; original sources contain them.

Shared calling contract

  • Types: counts, IDs, characters, counters, timestamps, and numeric codes use signed Int64. Buffers and session handles use CPointer<Int64>. Each logical byte occupies one whole word and must be in 0..255; these are not packed byte arrays. Text lengths exclude any terminator.
  • Ownership: callers own sufficiently large, live input and output buffers. A session must be a live authNew result, must not be modified outside these operations, and must eventually be destroyed. Capacities are caller obligations; pointers are not validated.
  • Aliasing: output buffers must not overlap inputs or session storage. Input buffers must not overlap session storage. Read-only inputs may overlap each other. Do not access a session after destruction.
  • Concurrency: serialize all calls on a session, including reads, and synchronize destruction. Sessions are independent and hold at most 16 accounts.
  • Errors: Bool and negative status values report validation or lookup failures under the calling contract. Allocation failure, invalid pointers, insufficient capacity, and machine/runtime failures are not encoded as those statuses. Allocation success is assumed.
  • Scope: SHA-1 only; six- or eight-digit OTPs. Time is supplied explicitly. No persistence, networking, clock reads, URI parsing, text encoding, clipboard operations, or display formatting occur in the core. Adapters must zero-pad numeric codes.
  • Memory effects: scratch allocations are released before normal return. They are not uniformly scrubbed. Source-level overwrites do not establish guaranteed physical secret erasure. Heap refinements and reachable-state Int64 bounds are checked. Formal compiler correctness is outside the proof boundary.

Metadata output layout

authRead requires 260 output words. On success, interpret only these fields and the prefixes indicated by their lengths:

  • dst[0] — digits (6 or 8)
  • dst[1] — period in seconds
  • dst[2] — label length
  • dst[3] — issuer length
  • dst[4 .. 4 + labelLen) — label bytes; capacity 128 words
  • dst[132 .. 132 + issuerLen) — issuer bytes; capacity 128 words

Neither the secret nor its length is included. Unwritten gaps and tails retain their prior contents. No strings are null-terminated by this operation.

#
func authBase32Value(ch: Int64): Int64

Purpose

Convert a single Base32 alphabet character to its numeric value.

Arguments

ch: Int64
An Int64 character code. Uppercase and lowercase ASCII letters and digits 2 through 7 are recognized.

Return value

0..31 for an alphabet character, or -1 otherwise. The padding character = is not an alphabet value; authBase32 handles it separately.

Side effects

Pure scalar computation: no memory reads/writes through pointers, allocation, state mutation, or I/O.

authFind

#
func authFind(session: CPointer<Int64>, id: Int64): Int64

Purpose

Locate an account’s internal storage slot.

Arguments

session: CPointer<Int64>
A live session pointer returned by authNew; callers treat its layout as opaque.
id: Int64
An account identifier returned by authAdd; identifiers are positive and never reused within a session.

Return value

A slot index in 0..15 if the positive ID exists; -1 otherwise. This is an internal index, not an account identifier.

Side effects

Reads the 16 slots without modifying the session or allocating memory. Consumers should use authRead/authCode rather than depending on this index or the private slot layout. The implementation lemma relates the complete loop to scan_identifiers and preserves the session buffer.

Implementation contract: sessions.session_find_wp.
